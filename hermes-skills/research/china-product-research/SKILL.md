## 輸入收集

- **必須**：產品品類（如：中藥煲／空氣炸鍋／寵物飲水機）
- **可選（有默認值）**：目標市場（默認：內地為主，兼顧港/海外華人）、交付格式（默認 HTML + PPT 兩份）、語言（默認繁體中文）、是否視覺驗收（默認要）
- **自主模式規則**：用戶在自主/無人值守模式下時，用默認值直接開工，不要反問；只有品類本身缺失才提問。

先建 todo 清單（調研爆款 → 新亮點 → 源頭工廠 → HTML → PPT → 視覺驗收），逐項推進。

## 階段 1 · 調研（WebSearch + WebFetch，約 7–8 次搜索）

把下列模板中的 `{產品}` 替換成品類，逐條執行：

1. `{產品} 爆款 銷量排行 品牌 2025`（品牌格局）
2. `{產品} 京東 天貓 銷量排行榜 品牌推薦`（平台榜單）
3. 對銷量冠軍深挖：`{品牌} {型號} 價格 多少錢`（精確價格帶）
4. `{產品} 2025 新功能 賣點`（新亮點）
5. `1688 {產品} 源頭工廠 廠家直銷 批發`（B2B 價格）
6. `{產業帶城市} {產品} 產業帶 OEM ODM 代工 起訂量`（產業帶地理 + MOQ）
7. 補漏：頭部 2–3 個品牌的代表型號與海外華人渠道價（110V 版等）

高價值網頁，用 WebFetch 深挖全文：
- 京東排行榜頁（URL 含 `/phb/`）——銷量與評價量數據
- 買購網 maigoo 榜單頁——TOP10 產品表（品牌/型號/價格/特點）
- 百度健康品牌榜——品牌推薦與賣點文案
- 1688 批發頁——工廠名、批價、成交筆數
- 1688 產業帶百科（wiki.1688.com）——MOQ、貼牌條款

注意：知乎正文多數 403，放棄即可不要重試；淘寶/天貓商品頁需登入，靠搜索摘要取數。**每個數據點必須記錄：數值 + 來源 URL + 查詢日期**，報告末尾附完整來源清單。

## 階段 2 · 數據提煉（固定六表框架）

1. **頭號爆款 spotlight**：品牌｜型號｜價格（券後/原價）｜評價量｜規格｜核心賣點｜爆紅原因（以評價量最大者為準，通常京東自營款）
2. **熱門榜 TOP 5–10**：品牌｜型號｜參考價｜規格與特點（maigoo 榜單為骨架，京東數據校正）
3. **新功能亮點**：功能｜說明｜代表品牌——標註哪些已成標配、哪些是新興賣點
4. **源頭工廠表**：工廠名｜地點/年資｜主營｜批發價｜熱度（成交筆數）
5. **價格帶分析**：B2C 零售區間 vs B2B 批發區間 → 毛利空間結論；爆款密集價格區
6. **採購建議**：對標爆款定規格 → 三檔定價（批發成本/建議零售/毛利率）→ MOQ 與合規（電壓 110V/220V、3C/CE/UKCA、易碎品物流）

誠信規則：估算值一律標 `(est.)`；批發價是 1688 掛牌價，必須註明「實際以議價為準」；評價量/成交筆數註明查詢時點，因為會隨促銷浮動。

## 階段 3 · HTML 報告（Write 一次成型）

單檔內嵌 CSS，結構固定六部分：

1. hero 頭部（品類名 + 副題 + 日期 + 資料來源渠道）
2. 目錄（錨點）
3. ① 市場概況：4 個 KPI 卡（零售價帶/批發價帶/主流規格/冠軍銷量）+ 渠道結構表（B2C/B2B/出口代工三行）
4. ② 爆款：頭號爆款 spotlight 卡 + TOP10 榜單表 + 其他值得關注款 + 爆款規律總結
5. ③ 新功能亮點表（含「注意」類反向提示，如某宣稱功能實際少見）
6. ④ 源頭工廠表 + 產業帶說明 + 尋源渠道三步
7. ⑤ 選品建議：規格對標 + 定價毛利表 + 落單合規清單
8. ⑥ 資料來源清單（帶超連結）+ 免責腳註（價格浮動聲明）

配色從品類抽取（中藥煲→棗紅 #8A2B2B + 陶土金 #C9962E），不要默認藍色。表格斑馬紋、callout 色塊、@media print 友好。

## 階段 4 · PPT（必須先載入 `presentations:pptx` 技能）

10 頁模板（13.33×7.5 LAYOUT_WIDE）：

| # | 頁面 | 佈局要點 |
|---|------|---------|
| 1 | 封面 | 深色底 + 超大標題 + 品類圓形 motif + 兩條關鍵結論預告 |
| 2 | 市場概況 | 4 KPI 卡（超大數字）+ 渠道結構行（標籤膠囊+描述+右對齊價格） |
| 3 | 頭號爆款 | 左深色面板（NO.1 + 大字價格 + 評價量）+ 右規格編號行 + 底部「爆紅原因」色帶 |
| 4 | TOP10 榜 | 原生橫向條形圖（價格，極值金色高亮）+ 右側 4 張速讀卡 |
| 5 | 新亮點 | 6 條 2 欄×3 行，大編號 01–06，底部趨勢/注意色帶 |
| 6 | 爆款規律 | 三層價格階梯（寬度與深度遞增）+ 目標人群小卡 |
| 7 | 源頭工廠 | 左產業帶示意圖（深色大框+chips+連線到衛星城市）+ 右工廠表 + OEM 門檻綠色 callout |
| 8 | 定價毛利 | 原生分組柱狀圖（批發成本 vs 建議零售，兩系列）+ 右毛利率卡（標 est.） |
| 9 | 選品三步走 | 三張步驟卡（①對標②定價③落單）+ 深色傳播鉤子橫幅 |
| 10 | 封底 | 深色底 + 金句總結 + 4 數據卡 + 下一步 + 免責腳註 |

技術陷阱清單（違反即檔案損毀或走樣）：hex 不帶 `#`；透明度用 `opacity`/`transparency` 屬性而非 8 位 hex；`LAYOUT_WIDE` 必須顯式設定；中文字體顯式指定（繁體 Microsoft JhengHei、簡體微软雅黑，都是用戶 Windows 自帶）；bullet 與 shadow 用工廠函數返回新物件；rich text 陣列每項 `breakLine: true`；圖表用原生 `addChart`（不要截圖）；不用色條/標題底線/滿屏卡片格。**生成腳本存為 `build_ppt.js` 並保留**——用戶日後改頁面時重跑即可，不要丟棄。

## 階段 5 · 渲染驗收與交付

用 `scripts/render_deck.py` 一鍵渲染（自動找 soffice，PDF→PNG）：

```bash
python "<skill目錄>/scripts/render_deck.py" <deck.pptx> <out_dir> [dpi=110]
```

然後派 `presentations:visual-judge` 子代理逐頁檢查（文字溢出/元素重疊/圖表標籤可讀/對比度/中文亂碼），修復後復檢，通過才交付。

交付規範：
- 用 `::zcode-file-citation{path="..." purpose="output"}` 引用每個最終檔案各一次（內文引用，不要另貼路徑清單）
- 先給 TLDR：頭號爆款（品牌/型號/價格）+ 一句新亮點總結 + 產業帶/OEM 門檻 + 建議切入價位
- 清理 `render/` 中間檔（PDF、PNG）；保留 `build_ppt.js` 和 `.html`、`.pptx`
- **用戶催促跳過驗收時**：直接交付，但聲明「未經最終視檢，發現問題報頁碼可即時修復」——不要默默跳過
